# Импорт MCAD из Excel

Импорт сохраняет исходные поля, ссылки и происхождение данных. Исходный XLSX читается локально и не изменяется; формулы не выполняются. Файл, отчёты и БД не должны попадать в Git или в `frontend/public`: для них используется игнорируемая папка `data/`.

После установки Python-зависимостей и настройки `DATABASE_URL` создайте схему и выполните импорт из корня проекта:

```sh
python -m mcad migrate
python -m mcad.import_workbook /path/to/MCAD.xlsx --report data/import-report.json
```

Для проверки без подключения к БД добавьте `--dry-run`. Адрес БД берётся из конфигурации сервера, а не из аргументов команды; не сохраняйте пароль подключения в документации. Исторический импорт всегда использует `notify=False`: существующие 440 записей не создают Telegram-уведомлений.

## Состав проверенного источника

В версии, исследованной 2026-10-22, лист `Database` содержит **440 непустых записей**, 33 именованных поля, 9 пустых завершающих строк и две пустые колонки. Все записи имеют заголовок, год и номер ссылки. Автофильтр источника заканчивается на строке 425, но записи продолжаются до строки 441; импорт читает все непустые строки независимо от фильтров.

Номеров ссылки 431: девять номеров используются для двух разных записей. Они не объединяются. Внешний идентификатор формируется из номера и SHA-256 нормализованного заголовка; перестановка строк его не меняет. Если однажды появятся одинаковые номер и заголовок, добавляется отпечаток исходных значений и порядковый номер точного повтора. Изменение самого заголовка требует ручного сопоставления со старой записью: импорт не угадывает, относится ли исправление к прежнему инциденту.

Повторный импорт файла с тем же SHA-256 возвращает существующий пакет импорта, создаёт ноль записей и ноль уведомлений. Другой файл с теми же внешними идентификаторами обновляет соответствующие записи. Весь пакет записывается одной транзакцией: ошибка БД откатывает пакет целиком.

## Поля и связи

Все 33 поля доступны как нормализованные поля БД. `Reference URL` разбирается в отдельные ссылки; `Victim identity`, `Threat Actor` и местоположение связаны с записью через дочерние таблицы. Составные названия организаций и акторов не разделяются по запятым автоматически: такая запятая может быть частью имени.

В `raw_fields` остаются оригинальные заголовки с пробелами и исходные значения. `_cells` содержит адреса ячеек, Excel-типы и форматы, текст формул, их сохранённые значения и обычные гиперссылки. Сохраняются различия между `null`, пустой строкой и пробелами. `_source` содержит SHA-256, лист и строку источника; `_country_relations` связывает каждую страну с ролью и кодом из листа `lists`.

В метаданных `ImportBatch` сохраняются все непустые строки `lists`, исходные определения таблиц и валидации, именованные диапазоны и справочники. В источнике 249 ISO-кодов, отдельное значение `Other` без кода и строка со ссылкой на происхождение справочника; последние две строки сохраняются как исходные данные и не превращаются в страны. Справочники содержат 3 области воздействия, 13 методов и 9 типов жертв. Их значения не ограничивают импорт: новые и составные категории сохраняются.

`USA`, `UK`, `UAE` и известные варианты названий сопоставляются с кодами справочника. Очевидные варианты написания `Ukarine`, `Vietman`, `Libanon` также нормализуются, а исходное написание остаётся в `raw_fields`. Неопределённые значения и регионы не получают выдуманный код страны. Например, `Asia Region` и `Geoje-si` остаются неразрешёнными значениями для проверки.

## География и даты

**426 записей** имеют координаты из источника, **14** остаются без точки. Одна исходная пара разделена пробелами вместо запятой; она разбирается без геокодирования. Из 14 записей без координат одна описывает несколько городов, восемь содержат только страну, пять не имеют ни страны, ни места.

Исходные точки могут обозначать порт, город, столицу, регион или приблизительную позицию. В 152 строках текст места совпадает с названием страны. Они помечены `location_precision=source_provided`; это не подтверждение точного места атаки. Импорт не запрашивает внешний геокодер, не подставляет центры стран и не меняет местами широту и долготу. Некорректные или отсутствующие координаты сохраняются в исходных полях, а запись остаётся в БД и списке без маркера. 426 записей используют 365 различных числовых точек; совпадающие координаты не служат причиной объединять инциденты.

Год сохраняется отдельно от месяца и конечного года. У 63 записей месяц неизвестен; 13 записей охватывают несколько лет. Точного дня в источнике нет, поэтому `date_start` остаётся `null`, а `date_text` и `date_precision` отражают месяц, год или диапазон. Последние цифры номера ссылки не трактуются как день. В одном случае год номера расходится с колонкой `Year`; используется явно указанная колонка, а расхождение попадает в отчёт.

## Контроль полноты

Отчёт показывает число исходных, принятых, помещённых на проверку, отображаемых и неотображаемых на карте строк, предупреждения и ID пакета. Каждая непустая строка должна соответствовать инциденту либо сохранённой исходной строке с причиной проверки. Строка без обязательного заголовка сохраняется в карантине и `ImportRow`, а не исчезает. Для текущего источника: 440 принятых строк, 0 в карантине, 426 точек, 14 записей без точки.

Проверки парсера, атомарности, карантина и тихого повторного импорта:

```sh
python -m pytest tests/test_import_workbook.py
MCAD_TEST_WORKBOOK=/path/to/MCAD.xlsx python -m pytest tests/test_import_workbook.py
```

Первый вариант выполняет автономные проверки; второй дополнительно проверяет фактический частный источник, все 440 записей, сохранность файла и повторный импорт в временную SQLite-БД. Исходный файл не требуется и не публикуется в CI.
