# MCAD: карта, база данных и Telegram

Приложение размещается в проекте **MCAD** на Railway. Один сервис `mcad-web` обслуживает React, API, очередь новостей и Telegram; отдельный PostgreSQL хранит данные. БД подключена к приложению по приватной сети. Публичный TCP-доступ к PostgreSQL не нужен.

- Карта: `https://mcad-web-production.up.railway.app/`
- Управление: `https://mcad-web-production.up.railway.app/admin`
- Проверка состояния: `https://mcad-web-production.up.railway.app/api/health`
- Проект Railway: `https://railway.com/project/96a0bb80-be8f-40a2-86f0-d9221c596247`

Сервис связан с репозиторием `MichelleCovali/mcad-bot`, ветка `codex/mcad-map-frontend`.
Изменения размещённого приложения нужно отправлять в эту ветку.

При первичном развёртывании 22 октября 2026 года импортированы 440 записей:
426 с исходными координатами и 14 без точки. Повторная загрузка того же файла
создала 0 записей и 0 событий уведомлений. Поля и ссылки сохранены; исходный
Excel не изменён. Живой Telegram включается после добавления действующего
`TELEGRAM_BOT_TOKEN`; без него сервер не обращается к Telegram.

## Как поступают новые данные

1. Исторический Excel импортируется через защищённую страницу управления. Все исходные поля, ссылки и происхождение сохраняются. Повтор того же файла не создаёт новые записи. Исторический импорт не запускает рассылку.
2. RSS-проверка каждые 15 минут помещает подходящие новости в очередь кандидатов. Совпадение ключевых слов не считается подтверждением инцидента.
3. Администратор проверяет новость, указывает сведения о событии и местоположении и публикует запись. Можно также добавить новый инцидент вручную.
4. Запись и событие для уведомлений сохраняются в одной транзакции. Карта обновляет данные каждые 45 секунд и при возвращении на вкладку.
5. Сервер отправляет уведомления подписанным чатам со ссылкой на карточку. Изменение существующей опубликованной записи повторную рассылку не создаёт.

## Управление и секреты

Для входа на `/admin` используется `ADMIN_API_TOKEN`, заданный в **Railway → MCAD → mcad-web → Variables**. Токен администратора хранится только на сервере и в памяти открытой страницы после ввода; в JavaScript-сборку, Git и адресную строку он не попадает.

Основные переменные сервера:

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Приватная ссылка на PostgreSQL: `${{Postgres.DATABASE_URL}}` |
| `ADMIN_API_TOKEN` | Ключ защищённого управления и импорта |
| `PUBLIC_BASE_URL` | Публичный адрес карты для ссылок Telegram |
| `TELEGRAM_BOT_TOKEN` | Действующий токен вашего бота |
| `TELEGRAM_CHAT_ID` | Необязательный заранее согласованный чат для уведомлений |
| `ENABLE_BACKGROUND_WORKERS` | `true` в размещённом сервисе |
| `ENABLE_FEED_POLLING` | `true` для автоматической очереди новостей |
| `ENABLE_TELEGRAM_POLLING` | `true` для команд Telegram |

Токены и выгрузки не нужно добавлять в Git. Рабочая папка `/data/`, локальные `.env`, Excel и зависимости исключены из коммитов. Исходный Excel не включается в образ или публичные файлы сайта. При импорте он обрабатывается во временной папке сервера и удаляется после обработки; поля и метаданные происхождения сохраняются в БД.

## Подключение Telegram

Добавьте `TELEGRAM_BOT_TOKEN` в переменные `mcad-web` и перезапустите/разверните сервис. В личном чате с ботом отправьте `/subscribe`. Доступны `/unsubscribe`, `/latest`, `/map` и `/help`. Если задан `TELEGRAM_CHAT_ID`, он регистрируется как получатель; явная отписка сохраняется после перезапуска.

Один и тот же токен не должен одновременно использоваться старым отдельным `commands.py` и новым размещённым сервисом. Старый `bot.py` рассылает RSS-ссылки по прежней логике и обходит проверку кандидатов; после перехода используйте размещённый сервис.

Уведомления имеют устойчивую очередь, отдельный статус по получателю и повтор после временной ошибки/ограничения Telegram. Telegram не предоставляет ключ идемпотентности для отправки сообщения: при аварии между фактической доставкой и фиксацией ответа редкий повтор всё ещё возможен. Исторические импорты уведомлений не создают вообще.

## Локальная разработка

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
# Задайте свой ADMIN_API_TOKEN в .env, если нужно локальное управление.
.venv/bin/python -m mcad migrate
.venv/bin/python -m uvicorn mcad.api:app --host 127.0.0.1 --port 8090
```

В другой вкладке терминала:

```sh
cd frontend
npm ci
npm run dev
```

Vite перенаправляет `/api` на локальный порт 8090. По умолчанию локальные фоновые процессы отключены в `.env.example`, чтобы разработка не отправляла сообщения.

Для CLI-импорта используйте инструкцию в [data-import.md](data-import.md). Для PostgreSQL передайте `DATABASE_URL` через защищённое окружение, а не аргумент командной строки. Схема обновляется командой `python -m mcad migrate`; применённые миграции не редактируйте.

## Развёртывание и данные

`Dockerfile` собирает фронтенд и запускает один процесс Uvicorn с серверными работниками. `railway.toml` задаёт проверку `/api/health`. При переходе на PostgreSQL без `DATABASE_URL` размещённый сервис останавливается, а не создаёт временную SQLite-базу.

Постоянный том PostgreSQL сохраняет записи при обновлениях приложения. Наличие тома не заменяет резервные копии: перед изменениями схемы или большим обновлением данных создавайте backup в Railway и сохраняйте исходные файлы импорта. Приложение не удаляет исторические записи при повторном импорте.
